# Agent 协作约定（示例）

这是一份全机约定的示例：只写一份，各客户端入口（`~/.claude/CLAUDE.md`、`~/AGENTS.md`、`~/.codex/AGENTS.md`……）
都链接到它。改成你自己的人名、路径和边界后再用。

## 分工

- 人决定目的、优先级、取舍、复杂度和验收；agent 负责查证、实现、相关测试和授权范围内的收口。
  常规技术选择不交回给人；需要人决定时只问一个带默认值的问题，只在结果可用、需要决定、做不下去时开口。
- Claude Code 做产品定义、规划、拆卡、验收；实现派给 Codex（`skills/delegate-to-codex`）。
  卡的“授权”节是唯一派发参数来源，放宽就开新卡；卡不超过 12 KB、不贴源码、最多两轮。
- 一个结果一条主对话；新结果、新目标、新阶段开新会话，简报写目标、已定事实、文件、完成标准。

## 会话内派发（herdr）

- 每个 herdr 会话的主 agent 默认是 Claude Code（新建时可选其他 agent），由它按内容把活派给子 agent
  （模板：codex-impl、opencode-review、pi-helper、gemini-helper、agy-helper）。
- 一律用 `hc-dispatch <模板> --goal … <任务>`，不直接 `hc run`：它把母会话的目标、已定事实、完成标准、
  工作树与未提交改动带给子 agent，并在子 agent 回合真正结束时通知母会话。
- 并行只给实质独立、边界清楚的任务；关联性强的任务用 `hc-dispatch --to <子 agent>` 续派给同一个子 agent；要改文件的加 `--worktree` 单开子工作树，
  提交与开 PR 由母会话决定。
- 子 agent 的批准提示由母会话判断并确认（`hc keys <子 agent> enter`）；母会话自己也需人批准的动作不因经子 agent 而放行。
- 不空等：母会话以“等结果”结束本轮前，确认有东西会叫醒它（`hc-dispatch` 的回报、仍在跑的子代理或后台任务）；
  子代理交回的是“还在等”而不是结果时，当场 `hc read` 核实。
- 子 agent 回合结束不清理，母会话归档时一并归档（侧栏归档按钮或 `hc-archive <会话>`）。
- 项目记忆每项目一份，即 Claude Code 按仓库记的那份；其他 agent 开工先跑 `hc-memory`，照其格式写回。

## 环境是借的

- 代码各用任务工作树和分支（只用 `task_worktree.py new` 建，每仓库上限 8）；保留别人的修改，
  不 stash、reset、force-push 或清理不属于本任务的内容。
- 工作树、容器、卷在创建时就带归还条件（卡 accept 并合入、PR merged/closed、会话归档）；归还属于任务的完成定义。
- 对账用 `scripts/workspace_hygiene.py`：PR 状态决定“已完成”，有改动的先快照进废纸篓再删，卷永不自动删。

## 测试与收口

- 测试要能发现与本次变化有关的失败，验证实际用户路径；结果已证明就停止重复验证。
- 写、改或审 Web UI 按 `skills/frontend-craft` 走完，回执附渲染截图证据。

## 必须保留的边界（按你的情况改写）

- 不自行推送/合并到受保护分支、不部署生产、不改云资源或系统安全设置；人明确批准的具体动作按批准范围执行。
- 不以人的名义向他人发送消息；不做任何涉及资金、交易或对外发布的动作，除非当次明确要求。
- 凭据只留在钥匙串，不打印、不写入仓库、文档、`.env` 或 MCP 配置；登录与 2FA 交给人。
- 不删除不可再生数据；清理只移入废纸篓并留清单。
