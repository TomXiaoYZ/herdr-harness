# 任务卡：项目交接文档

- 派出：<YYYY-MM-DD>，Claude Code
- 仓库：<仓库根路径>
- 工作树：<仓库根>/.worktrees/codex-handoff-<YYYYMMDD>
- 分支：task/codex-handoff-<YYYYMMDD>（基于 <默认分支>）
- Codex 线程：<thread id>

## 目标

这个仓库此前主要由 Codex 开发。从现在起由 Claude Code 负责产品定义、规划、拆任务和验收，
Codex 负责既定规格内的实现。Claude Code 需要一份能让它独立做规划决定的交接文档：
现状是什么、哪些在做一半、哪些坑不能踩、怎么跑起来验证。

## 产出

`docs/handoff/<YYYY-MM-DD>-codex-handoff.md`，中文，结论先行，每条事实给出处（文件路径、分支、
提交、线程名或命令输出）。内容按以下结构，没有的小节写“无”，不要凑：

1. **一句话定位**：产品是什么、给谁用、现在处于什么阶段。
2. **代码地图**：顶层目录各自负责什么；跨层边界和不能违反的架构约束（引用 AGENTS.md 已有条目即可，不复制）。
3. **怎么跑、怎么验**：本地启动、测试、lint、构建的实际命令；哪些检查慢、哪些有已知失败。
4. **进行中的工作**：未合并分支、Codex 工作树、未完成的改动各自做到哪一步、下一步是什么、能否直接接手。
5. **最近 30 天做了什么**：按主题归纳，不逐条列提交。
6. **已知问题与坑**：踩过的坑、反复出现的失败、脆弱的地方。
7. **待决定事项**：需要用户拍板的产品或技术取舍，各给一个建议默认值。
8. **外部依赖与环境**：服务、账号、密钥的名字和用途（只写名字和去哪里找，不写值）。
9. **建议 Claude Code 先看的 5 个文件**。

## 验收标准

1. 文档存在于上述路径，各小节齐全，事实都有出处。
2. 第 3 节的命令由 Claude Code 实际执行一遍能对上文档描述（慢检查可只核命令存在）。
3. 第 4 节列出的分支和工作树与 `git branch -a`、`git worktree list` 一致。
4. 主检出工作区未被改动；改动只在工作树内，只新增这一份文档。

## 边界

- 只在工作树内读写和执行 git；可以读主检出和 Codex 工作树的文件与 git 历史，不改它们。
- 不 push、不改代码、不改配置、不装依赖、不跑部署；不读取或写入密钥值。
- 可以运行只读命令（git log、ls、cat、测试列表），不运行会改状态的脚本。
- 事实不确定就标“未核实”，不猜。

## 完成定义

文档写入工作树并自检完各小节为止。不要执行 `git add`/`git commit`：提交由 Claude Code
验收后完成（链接工作树的 git 元数据对你是只读的）。
